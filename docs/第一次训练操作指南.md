# 第一次 nanoGPT 训练：复制命令、观察结果、继续训练

适用环境：本项目已经准备好的 Windows PowerShell、RTX 3050 Laptop 4GB、Python 3.12 与 `.venv-pretrain`。数据使用已有 Shakespeare 字符语料，模型从随机权重开始。

**操作路线：环境检查 → 训练约 100 步 → 生成文本 → 从检查点继续到 2000 步 → 比较生成结果。** 建议逐节执行，先看输出再进入下一节。本文命令由你手动执行，编写本文时没有启动训练。

配套阅读：[nanoGPT 源码导读](./nanoGPT源码导读.md)。

## 0. 先知道本次要观察什么

这次训练的是约 81 万参数的英文字符续写模型，目标是学会预测下一个字符。它不会因为完成本次训练就能像聊天助手一样回答问题。

本次固定配置：

| 项目 | 设置 |
|---|---|
| 模型 | 4 层、4 个注意力头、隐藏维度 128 |
| 输入窗口 | 128 个字符 |
| 微批次 | 4 段文本 |
| 梯度累积 | 4 次前向/反向后尝试更新一次 |
| 每轮训练 token | `4 × 128 × 4 = 2048`，含重复抽样 |
| 精度 | CUDA autocast FP16 |
| 编译 | 关闭 |
| 学习率 | 100 步预热，之后余弦下降，到 2000 步达到最低值 |
| 保存方式 | 每次评估都保存到同一个 `ckpt.pt`，保留最近的评估检查点 |

训练时重点观察：`train loss`、`val loss`、耗时、显存，以及训练前后生成的文字形态。不要把日志中的 `mfu` 当成这张 3050 的真实利用率，源码使用了 A100 的峰值参照。

## 1. 打开 PowerShell，进入已有环境

接通电源，保证散热，关闭不需要的大型应用。如果已经运行了其他本地模型，先正常停止它们。

打开一个 PowerShell 窗口，复制：

```powershell
$ProjectDir = 'D:\workspace\pretrain-model'
$TrainPython = Join-Path $ProjectDir '.venv-pretrain\Scripts\python.exe'
Set-Location (Join-Path $ProjectDir 'nanoGPT')

if (-not (Test-Path -LiteralPath $TrainPython)) {
    throw "找不到预训练 Python：$TrainPython"
}
& $TrainPython --version
& $TrainPython -m pip check
if ($LASTEXITCODE -ne 0) { throw '依赖检查失败，先处理上面的报错。' }
```

预期看到 Python 3.12.x 和 `No broken requirements found.`。直接使用虚拟环境内的解释器，不需要激活脚本，也不需要重新安装 PyTorch。

**后面的命令默认在这个 PowerShell 窗口接着执行。** `$TrainPython` 等变量只在当前窗口有效；关闭窗口后的恢复方式见第 9 节。

## 2. 检查 GPU、内存和数据

### 2.1 GPU 计算检查

```powershell
& $TrainPython (Join-Path $ProjectDir 'check_gpu.py')
if ($LASTEXITCODE -ne 0) { throw 'GPU 计算检查失败，先不要进入训练。' }
nvidia-smi

$SystemMemory = Get-CimInstance Win32_OperatingSystem
'可用内存：{0:N2} GiB' -f ($SystemMemory.FreePhysicalMemory / 1MB)
```

`check_gpu.py` 会执行一个很小的 GPU 前向、反向运算，用于确认 PyTorch 能计算；它不是语言模型训练。

预期包含：

```text
PyTorch: 2.8.0+cu126
CUDA available: True
GPU: NVIDIA GeForce RTX 3050 Laptop GPU
GPU forward/backward OK; loss: ...
```

GPU 检查里的 loss 是随机矩阵计算结果，与后面语言模型 loss 无关。系统可用内存尽量留出约 6GiB；这是项目已有指南的保守起步建议，不是硬性框架阈值。

## 3. 建立本次实验目录和通用参数

复制下面整个代码块。它为每次实验生成新的目录名，方便保留旧实验。

```powershell
$RunName = 'out-first-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
$RunDir = Join-Path (Get-Location).Path $RunName
New-Item -ItemType Directory -Path $RunDir -ErrorAction Stop | Out-Null
Set-Content -LiteralPath (Join-Path $RunDir 'run-path.txt') -Value $RunDir -Encoding UTF8

$CommonArgs = @(
    'config/train_shakespeare_char.py'
    '--device=cuda'
    '--compile=False'
    '--dtype=float16'
    '--n_layer=4'
    '--n_head=4'
    '--n_embd=128'
    '--block_size=128'
    '--batch_size=4'
    '--gradient_accumulation_steps=4'
    '--bias=False'
    '--dropout=0.2'
    '--learning_rate=0.001'
    '--min_lr=0.0001'
    '--warmup_iters=100'
    '--lr_decay_iters=2000'
    '--always_save_checkpoint=True'
    '--wandb_log=False'
    '--log_interval=10'
    "--out_dir=$RunName"
)
$CommonArgs | Set-Content -LiteralPath (Join-Path $RunDir 'common-args.txt') -Encoding UTF8
'本次实验目录：' + $RunDir
```

记住最后打印的目录。训练日志、检查点和生成结果都会放在这里。`@CommonArgs` 是 PowerShell 把数组逐项作为命令参数传入的语法。

这里主动设置 `always_save_checkpoint=True`，使第一次练习能在第 50、100 步得到可加载的检查点；代价是 `ckpt.pt` 表示最近一次评估保存的模型，不保证是验证集表现最好的模型。

通用参数没有设置 `init_from`，后面会分别指定 scratch 和 resume。

## 4. 第一段：从零训练约 100 步

开始前，确认第 1—3 节都执行成功。下面这条会真正启动训练：

```powershell
& $TrainPython -u 'train.py' @CommonArgs '--init_from=scratch' '--max_iters=100' '--eval_interval=50' '--eval_iters=10' 2>&1 |
    Tee-Object -FilePath (Join-Path $RunDir 'train-100.log')
if ($LASTEXITCODE -ne 0) { throw '训练进程报错，请保留终端输出和 train-100.log。' }
```

`-u` 让 Python 尽量即时输出日志；`Tee-Object` 同时显示和保存输出。运行过程中当前窗口忙碌是正常的，等 PowerShell 提示符重新出现再执行下一条命令。

### 4.1 启动时看什么

先会打印许多 `Overriding` 参数覆盖信息，随后应包含：

```text
tokens per iteration will be: 2,048
found vocab_size = 65 ...
Initializing a new model from scratch
number of parameters: 0.80M
```

`0.80M` 是源码默认不含位置 embedding 的统计口径，完整参数数为 812,288。最关键的是 `from scratch`，说明起点是随机权重。

若参数量、token 数或词表大小明显不同，先核对命令和工作目录。

### 4.2 训练中看什么

你会看到以下结构，省略号代表实际数值，不是预测结果：

```text
step 0: train loss ... val loss ...
iter 0: loss ..., time ...ms, mfu ...%
iter 10: loss ..., time ...ms, mfu ...%
...
step 50: train loss ... val loss ...
saving checkpoint to out-first-...
...
step 100: train loss ... val loss ...
saving checkpoint to out-first-...
```

| 输出 | 该怎么理解 |
|---|---|
| `step 0` | 更新前的初始模型评估，可以作为 loss 基线 |
| `step ... train loss / val loss` | 关闭 dropout 后，随机抽多批数据计算的平均值 |
| `iter ... loss` | 当前训练循环最后一个微批次的 loss，波动很正常 |
| `time` | 该轮耗时；评估、保存附近会更慢 |
| `saving checkpoint` | 当前权重与优化器状态正在落盘 |
| `mfu` | 本实现的估算指标，第一次练习不以它判断训练成败 |

对于 65 个候选字符，完全均匀预测的理论 loss 约为 4.174，初始模型可能在附近，但不会恰好固定为这个数。训练有效时通常能看到总体下降，不要求每一行都比前一行小。

这段处于预热阶段，主要验证“读取数据 → 计算 → 更新 → 保存”的链路；100 步生成很差也不奇怪。

### 4.3 100 步的实际边界

本地源码从编号 0 开始，退出条件是 `iter_num > max_iters`，因此这个命令实际执行 101 次更新循环。

第 100 步的 checkpoint 在该轮更新之前保存，记录的是此前 100 轮之后的模型。循环最后多做的一轮没有再次保存。后面 resume 从磁盘记录的第 100 步继续；这是当前源码的行为。

### 4.4 想同时看 GPU

另开一个 PowerShell 窗口，执行：

```powershell
nvidia-smi -l 2
```

每 2 秒刷新一次。用该窗口的 `Ctrl+C` 结束监控，不影响另一个窗口的训练。观察显存占用、GPU 利用率、温度是否随训练变化。

## 5. 检查保存结果，生成第一段文字

回到训练窗口，先检查并留存第 100 步检查点：

```powershell
$CheckpointPath = Join-Path $RunDir 'ckpt.pt'
if (-not (Test-Path -LiteralPath $CheckpointPath)) {
    throw '没有找到 ckpt.pt，请先检查训练日志，不要继续生成。'
}
Get-Item -LiteralPath $CheckpointPath | Select-Object FullName, Length, LastWriteTime

$SnapshotDir = Join-Path $RunDir 'snapshot-100'
New-Item -ItemType Directory -Path $SnapshotDir -ErrorAction Stop | Out-Null
Copy-Item -LiteralPath $CheckpointPath -Destination (Join-Path $SnapshotDir 'ckpt.pt')
```

`snapshot-100` 单独留一份用于比较，后续训练会覆盖主目录的 `ckpt.pt`。这一节留存命令只执行一次；若提示目录已存在，说明之前已留存，请检查现有文件即可。

随后生成两段文本：

```powershell
& $TrainPython -u 'sample.py' "--out_dir=$RunName" '--device=cuda' '--compile=False' '--dtype=float16' '--start=ROMEO:' '--num_samples=2' '--max_new_tokens=200' '--temperature=0.8' '--top_k=65' '--seed=1337' 2>&1 |
    Tee-Object -FilePath (Join-Path $RunDir 'sample-100.txt')
if ($LASTEXITCODE -ne 0) { throw '生成失败，请先查看报错；暂不继续长训练。' }
```

预期输出从 `ROMEO:` 开始，后面可能是杂乱字符，也可能已经有空格、英文片段。这里没有唯一的“标准生成答案”。

先用英文提示。字符表没有通用中文编码能力，直接输入“你好”会失败，而不是切换成中文聊天。

**通过这一节，你才确认检查点真的能重新加载并用于推理。** 仅有 `ckpt.pt` 文件存在，还不足以确认整条链路正常。

## 6. 第二段：接着训练到 2000 步

第一段训练和生成都成功后，在同一个窗口执行：

```powershell
& $TrainPython -u 'train.py' @CommonArgs '--init_from=resume' '--max_iters=2000' '--eval_interval=200' '--eval_iters=20' 2>&1 |
    Tee-Object -FilePath (Join-Path $RunDir 'train-2000.log')
if ($LASTEXITCODE -ne 0) { throw '继续训练报错，请保留 train-2000.log。' }
```

必须看到：

```text
Resuming training from out-first-...
```

若看到 `Initializing a new model from scratch`，就不是断点续训，应先检查 `init_from` 参数。

这次把训练进度上限设为 2000，不是额外增加 2000。起始计数来自 checkpoint，按本地循环边界，从 100 到 2000 会执行 1901 次更新循环；最终第 2000 步保存发生在该轮更新之前。

两段都使用预热 100、衰减终点 2000 的学习率设置，避免第一段已经把学习率衰减到底、第二段又突然更改计划。

resume 会加载权重、优化器和计数，但没有恢复全部随机数与 AMP scaler 状态，因此不保证与完全不中断的训练逐位相同。

### 怎样观察这段结果

- 对比第 200、400、600……2000 步的 `val loss`，看较长区间的趋势。
- 训练 loss 和验证 loss 都下降：是学到数据规律的积极迹象。
- 训练 loss 继续下降、验证 loss 持续上升：可能出现过拟合，不必为了达到步数硬撑。
- loss 出现 `nan`、`inf`，或者持续异常：中断并保留日志进行定位。
- 不预先承诺完成时间，先依据本机稳定阶段的每步耗时估计，再计入评估和保存开销。

第一段和第二段的 `eval_iters` 分别是 10 与 20，评估抽样量不同，比较总体变化即可，不把小幅差异解释成严格改进。

```powershell
Get-Content -LiteralPath (Join-Path $RunDir 'sample-100.txt')

```

重点看：

| 比较点 | 观察示例 |
|---|---|
| 字符排列 | 是否从杂乱字符变成更像英文的组合 |
| 空格与标点 | 是否开始出现合理的词间空格、冒号和换行 |
| 文本格式 | 是否更像人物名加对白的戏剧文本 |

同样提示、随机种子和采样参数有助于比较，但两次生成不是严格能力评测；它们也可能具有随机性或重复问题。不要以“能回答我的问题”作为本次字符预训练的目标。

## 9. 中断、关闭窗口后，怎么继续

### 9.1 主动停止

在训练窗口按一次 `Ctrl+C`，等待 Python 进程退出。已经保存的 checkpoint 通常仍可用于恢复；尚未保存的更新会丢失。尽量不要在正在打印保存提示时中断，避免打断文件写入。

不要连续启动多个训练进程争用同一张 4GB 显卡。

### 9.2 新窗口恢复变量

先列出已有实验目录：

```powershell
$ProjectDir = 'D:\workspace\pretrain-model'
$TrainPython = Join-Path $ProjectDir '.venv-pretrain\Scripts\python.exe'
Set-Location (Join-Path $ProjectDir 'nanoGPT')
Get-ChildItem -Directory -Filter 'out-first-*' | Select-Object Name, LastWriteTime
```

**下面唯一需要手动替换的是实验目录名**，填入你希望恢复的那个名字：

```powershell
$RunName = 'out-first-替换为你的实际时间戳'
$RunDir = Join-Path (Get-Location).Path $RunName
if (-not (Test-Path -LiteralPath (Join-Path $RunDir 'ckpt.pt'))) {
    throw '没有找到该实验的检查点，请检查 RunName。'
}
$CommonArgs = @(Get-Content -LiteralPath (Join-Path $RunDir 'common-args.txt'))
```

恢复时使用新的日志文件名，保留之前的日志：

```powershell
$ResumeLog = Join-Path $RunDir ('train-resume-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.log')
& $TrainPython -u 'train.py' @CommonArgs '--init_from=resume' '--max_iters=2000' '--eval_interval=200' '--eval_iters=20' 2>&1 |
    Tee-Object -FilePath $ResumeLog
if ($LASTEXITCODE -ne 0) { throw '恢复训练报错，请查看新日志。' }
```

这适用于还没有达到 2000 步的实验。若已经完成，不需要再执行；当前源码在进入循环前不检查是否已经达到上限，盲目重跑可能再执行更新。

## 10. 常见问题：先找对应情况

### 找不到 python、train.py 或 configurator.py

重新执行第 1 节，确认工作目录是 `D:\workspace\pretrain-model\nanoGPT`，解释器使用 `$TrainPython`。不要直接用系统中不确定指向哪里的 `python`。

### CUDA out of memory

先确认之前的训练进程和其他模型已经退出。若仍然不足，第一次尝试只把通用参数中的 `--batch_size=4` 改成 `--batch_size=2`，梯度累积从 4 改成 8，以保持每轮约 2048 个 token。用第 3 节重新建立新实验，记录这次变化。

仍不足再考虑更短的窗口。不要同时改变所有参数，否则不容易知道改善来自哪里。

### FutureWarning 或关于旧 AMP API 的警告

本地 nanoGPT 使用了一些旧接口，可能打印弃用警告。若后续仍持续打印正常训练日志，不等于训练失败。若出现 Traceback、非零退出或数值异常，保留完整报错再定位，不要只截取最后一行。

### Weights only load failed

本文不会预先改变加载行为。若 `sample.py` 或 resume 真遇到这个错误，先确认加载的是**你刚刚用这些命令生成的本地 checkpoint**。

对于这一可信本地文件，可在准备重新运行失败命令前设置：

```powershell
$env:TORCH_FORCE_NO_WEIGHTS_ONLY_LOAD = '1'
```

然后重新执行失败的采样或恢复命令，执行完立即清除：

```powershell
Remove-Item Env:TORCH_FORCE_NO_WEIGHTS_ONLY_LOAD -ErrorAction SilentlyContinue
```

这是当前 PowerShell 及其子进程范围的兼容开关，让没有显式指定 `weights_only` 的加载调用使用完整反序列化；它不修改源码，不写入系统永久设置。不要用这项设置去加载来历不明的 checkpoint。

### 没有 ckpt.pt

这份指南已经启用每次评估保存，但第 0 步仍不会保存。检查是否在第 50 步之前就报错或被中断，以及是否查看了打印出的正确实验目录。不要对没有 checkpoint 的实验使用 resume。

### 训练结束，但输出仍然不通顺

先确认验证 loss 是否下降、采样加载的是哪一个目录、是否使用了英文提示。小模型、少量 Shakespeare 数据和有限训练量，只能提供教学级字符建模效果。先完成日志和生成对比，再决定下一轮只改哪个因素。

## 本指南的核验范围
