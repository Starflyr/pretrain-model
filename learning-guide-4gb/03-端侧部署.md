# 第三步：PC 本地部署与手机扩展

[第一步：环境准备与从零预训练](./01-环境与预训练.md) · [第二步：LoRA 微调与评估](./02-LoRA微调.md)

本机当前没有安装 Ollama。第一次学习可以先完成本页第 1 节，体验 0.5B 模型推理，再回到第一、二步；微调完成后从第 2 节继续，把自己的 adapter 变成可离线调用的模型。

本机 4GB 显存适合从 0.5B Q4、短上下文和单会话开始；1.5B Q4 只作为跑通后的推理扩展，不作为训练目标。D 盘约 188GB 可用，空间充足；真正需要提前处理的是当前系统内存余量过低和“降噪降频”电源模式。

## 端侧部署是什么

这里的“端侧”指模型在用户自己的设备上推理。电脑、Android 手机、iPhone 都可以是端侧设备，但适配方式不同。

- PC 本地推理：权重和计算都在你的电脑上，程序可以调用 `localhost` 上的模型服务。
- 手机本地推理：权重和计算都在手机上，下载完成后不依赖 PC 或云端模型。
- 手机页面调用电脑 API：是手机访问 PC 上的服务，不能据此宣称模型已经部署到手机端。

首次下载模型和工具需要联网；离线能力应在下载完成、模型加载成功之后验证。推理不更新模型权重。

## 1. 先用 Ollama 体验一次本地推理

从 [Ollama Windows 下载页](https://ollama.com/download/windows)安装，参考 [Windows 官方说明](https://docs.ollama.com/windows)。本实验不需要先安装 Python。

模型缓存放到项目根目录的 `ollama-models`，在 PowerShell 设置：

```powershell
Set-Location D:\workspace\pretrain-model
$PROJECT_ROOT = (Get-Location).Path
[Environment]::SetEnvironmentVariable("OLLAMA_MODELS", (Join-Path $PROJECT_ROOT "ollama-models"), "User")
```

设置后彻底退出托盘中的 Ollama 并重新启动，再打开新 PowerShell。已下载文件不会仅凭修改环境变量自动搬家，因此尽量先设置目录再下载。配置行为见 [Ollama FAQ](https://docs.ollama.com/faq)。

```powershell
ollama --version
ollama pull qwen2.5:0.5b
ollama run qwen2.5:0.5b
```

输入“用三句话解释什么是机器学习”。该标签为 [Ollama 模型库中的 Qwen2.5 0.5B](https://ollama.com/library/qwen2.5:0.5b)，是现成推理模型；运行它没有进行任何微调。

退出聊天输入 `/bye`。然后：

```powershell
ollama ps
ollama show qwen2.5:0.5b
```

查看实际运行位置、上下文和模型信息；不要仅凭“电脑里有 NVIDIA”就认定用了 GPU。模型先成功运行，再断开网络重复输入一条新问题，确认仍有本地生成结果。

训练前释放显存：

```powershell
ollama stop qwen2.5:0.5b
```

若 `ollama ps` 中还有其他模型，也逐个停止。0.5B 模型适合第一轮；后续可尝试 1.5B 量化模型，但序列长度、KV cache 和 GPU 分配仍需要实测。

## 2. 合并自己的 LoRA 模型

前提：已经完成 [LoRA 指南](./02-LoRA微调.md)，存在原始基座、`base-revision.txt` 和 `runs/lora-v1/adapter`。

```powershell
Set-Location D:\workspace\pretrain-model
& .\.venv-finetune\Scripts\Activate.ps1
Set-Location .\finetune
```

将下面内容保存成 `merge_lora.py`：

```python
from pathlib import Path
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel

ROOT = Path(__file__).resolve().parents[1]
BASE = ROOT / "models" / "qwen-base"
ADAPTER = ROOT / "finetune" / "runs" / "lora-v1" / "adapter"
OUT = ROOT / "models" / "qwen-merged"

# 在 CPU 上合并，避免占用仅有的 4GB 显存。
base = AutoModelForCausalLM.from_pretrained(
    BASE, torch_dtype=torch.float32, local_files_only=True,
)
model = PeftModel.from_pretrained(base, ADAPTER)
merged = model.merge_and_unload(safe_merge=True)
merged.config.use_cache = True
merged = merged.to(torch.float16)
merged.save_pretrained(OUT, safe_serialization=True)
AutoTokenizer.from_pretrained(BASE, local_files_only=True).save_pretrained(OUT)
print("已合并至", OUT)
```

```powershell
python merge_lora.py
python evaluate.py --model ..\models\qwen-merged --data data/test.jsonl --out merged-test.jsonl
```

此处合并的是约 0.5B 模型，本机 15.75GiB 内存总量足够作为起点，但检查时仅约 1.87GiB 可用，不能在这种状态下直接合并。先关闭重度应用或重启，在任务管理器确认余量；建议至少约 8GiB 可用再开始 CPU FP32 合并，并保留系统自动管理的页面文件。合并后数值精度变化可能导致边界样本输出不同；比较同一测试集，而不是假定每条输出逐字一致。

为什么不直接 `ADAPTER` 导入 Qwen？[Ollama 导入文档](https://docs.ollama.com/import)对直接导入适配器列有架构支持范围，不能推断任意 Qwen adapter 都受支持。本路线使用“合并完整权重 → GGUF → 导入”的方式衔接。

## 3. 转成 GGUF，转换依赖单独隔离

Safetensors 是训练生态常用的权重存储格式；GGUF 是 llama.cpp 等推理工具使用的模型容器格式。**文件格式转换不等于量化**：可以先得到 FP16 GGUF，再把它量化成 Q4_K_M。

```powershell
Set-Location D:\workspace\pretrain-model
git clone https://github.com/ggml-org/llama.cpp.git
py -3.12 -m venv .venv-convert
& .\.venv-convert\Scripts\Activate.ps1
python -m pip install --upgrade pip
Set-Location .\llama.cpp
git rev-parse HEAD > ..\llamacpp-revision.txt
python -m pip install -r requirements/requirements-convert_hf_to_gguf.txt
python convert_hf_to_gguf.py ..\models\qwen-merged --outfile ..\models\qwen-merged-f16.gguf --outtype f16
python -m pip freeze > ..\requirements-convert-resolved.txt
```

这些转换脚本随上游发展，会调整依赖；按本次检出的 requirements 安装，并保留 commit。转换环境与训练环境隔离，避免升级转换依赖时破坏微调环境。源代码和参数入口见 [llama.cpp 转换脚本](https://github.com/ggml-org/llama.cpp/blob/master/convert_hf_to_gguf.py)。

本步骤只运行 Python 转换器，后面交给 Ollama 推理，因此不用先编译 llama.cpp 的 CUDA 后端。如果日后想自己运行 `llama-cli`、`llama-server`，再参考[官方构建说明](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md)，或下载官方匹配系统的预编译程序。

## 4. 量化并导入 Ollama

在项目根目录的 `models` 文件夹中新建一个无扩展名的 UTF-8 文件 `Modelfile`，注意不要误存为 `Modelfile.txt`：

```text
FROM ./qwen-merged-f16.gguf
PARAMETER num_ctx 512
PARAMETER temperature 0
```

```powershell
Set-Location D:\workspace\pretrain-model
Set-Location .\models
ollama create my-qwen-f16 -f Modelfile
ollama create my-qwen-q4 --quantize q4_K_M -f Modelfile
ollama show my-qwen-q4
ollama run my-qwen-q4
```

第一条保留 FP16 参考模型，第二条才量化成 Q4_K_M。Q4_K_M 并不意味着所有数据严格等于每参数 4 bit，文件还包含不同精度张量与元数据；不要用“FP16 文件大小除以 4”当实际运行内存。

Ollama 的 GGUF 导入与 `--quantize` 参数见[官方导入说明](https://docs.ollama.com/import)。第一次使用 512 上下文、短输入、一个请求；跑通后再扩大到 1024/2048，观察 KV cache 和显存的变化。

检查 `ollama show my-qwen-q4 --modelfile` 与 `ollama show my-qwen-q4 --template`。转换应保留 tokenizer 和聊天模板信息；若显示空模板、输出角色标签或不停续写，就先排查模板识别，不要把它直接归因于“微调坏了”。可用原模型的 `ollama show qwen2.5:0.5b --template` 对照，并核对 HF tokenizer 中的 chat template。若需要手工配置，应保持角色标记、默认 system 与结束条件一致。

如果确实没有正确识别模板，可按以下步骤修复：

1. 执行 `ollama show qwen2.5:0.5b --modelfile`，把输出完整复制到 `models\Modelfile.qwen-template`。
2. 把其中的 `FROM ...` 行替换为 `FROM ./qwen-merged-f16.gguf`，保留 `TEMPLATE`、`SYSTEM`（若有）和 `PARAMETER stop`，加入或调整 `PARAMETER num_ctx 512` 与 `PARAMETER temperature 0`。不要保留原模型的 FROM 路径。
3. 执行 `ollama create my-qwen-q4 --quantize q4_K_M -f Modelfile.qwen-template` 重新创建；FP16 参考模型也用这个模板文件重新创建，省略量化参数。
4. 重新评估，检查实际 user/system 文本与 HF 路线一致。原模型模板只用于恢复同架构聊天格式，权重始终来自你自己合并的 GGUF。

## 5. 用自己的程序调用本地模型

保持 Ollama 后台运行。在 PowerShell 执行：

```powershell
$payload = @{
  model = "my-qwen-q4"
  messages = @(@{
    role = "user"
    content = "将客户留言分类为退款、物流、商品咨询、其他之一，只输出包含 intent 字段的 JSON。留言：货物到哪里了？"
  })
  stream = $false
  options = @{ temperature = 0; num_ctx = 512; num_predict = 48 }
} | ConvertTo-Json -Depth 10
$response = Invoke-RestMethod -Uri "http://localhost:11434/api/chat" -Method Post -ContentType "application/json; charset=utf-8" -Body ([System.Text.Encoding]::UTF8.GetBytes($payload))
$response.message.content
if ($response.eval_duration -gt 0) { $response.eval_count / ($response.eval_duration / 1e9) }
```

最后一行计算生成阶段的 token/s，不包括模型冷启动和完整请求耗时。接口字段见 [Ollama Chat API](https://docs.ollama.com/api/chat)。PC 上已有应用只需调用这个本地 HTTP 接口，就可以使用自己的模型。

如要把同一测试集交给 Ollama 自动评估，回到微调目录，将下面代码保存为 `evaluate_ollama.py`；它只用 Python 标准库：

```python
import argparse
import json
from pathlib import Path
from urllib.request import Request, urlopen

parser = argparse.ArgumentParser()
parser.add_argument("--model", required=True)
parser.add_argument("--out", required=True)
args = parser.parse_args()
rows = [json.loads(s) for s in Path("data/test.jsonl").read_text(encoding="utf-8-sig").splitlines() if s.strip()]
assert rows, "测试集为空"
results = []
for row in rows:
    body = {"model": args.model, "messages": [{"role": "user", "content": row["instruction"]}],
            "stream": False, "options": {"temperature": 0, "num_ctx": 512, "num_predict": 48}}
    request = Request("http://localhost:11434/api/chat", data=json.dumps(body).encode("utf-8"),
                      headers={"Content-Type": "application/json"})
    with urlopen(request, timeout=300) as response:
        result = json.load(response)
    answer = result["message"]["content"].strip()
    expected = json.loads(row["output"])
    try:
        parsed = json.loads(answer)
        valid = isinstance(parsed, dict) and set(parsed) == {"intent"} and parsed["intent"] in {"退款", "物流", "商品咨询", "其他"}
        correct = valid and parsed == expected
    except (json.JSONDecodeError, TypeError):
        valid, correct = False, False
    results.append({"instruction": row["instruction"], "expected": expected, "answer": answer,
                    "valid_schema": bool(valid), "correct": bool(correct),
                    "eval_count": result.get("eval_count"), "eval_duration": result.get("eval_duration"),
                    "total_duration": result.get("total_duration")})
Path(args.out).write_text("\n".join(json.dumps(r, ensure_ascii=False) for r in results), encoding="utf-8")
print("schema_valid_rate:", sum(r["valid_schema"] for r in results) / len(results))
print("task_accuracy:", sum(r["correct"] for r in results) / len(results))
```

```powershell
Set-Location D:\workspace\pretrain-model
Set-Location .\finetune
python evaluate_ollama.py --model my-qwen-f16 --out ollama-f16-test.jsonl
ollama stop my-qwen-f16
python evaluate_ollama.py --model my-qwen-q4 --out ollama-q4-test.jsonl
```

没有设置 `format=json` 或结构化输出约束，因为它们会额外保证格式，混淆微调前后的格式能力对照。温度设为 0 也不保证不同推理引擎、精度和设备上的输出完全一致。

## 6. 部署验收清单

| 项目 | 做法 |
| --- | --- |
| 模型身份 | `ollama show` 检查导入的是本次合并文件；名称与下载的原模型分开 |
| 离线运行 | 下载完成并加载过后断网，提交未问过的新输入 |
| 质量 | 对照 HF 基座、HF adapter、HF merged、Ollama FP16、Ollama Q4 的同一测试集结果 |
| 模板 | 检查角色、默认 system、停止条件；保持输入格式一致 |
| 性能 | 记录冷启动请求与热启动请求的总耗时、生成 token/s、上下文长度 |
| 资源 | `ollama ps`、`nvidia-smi`、任务管理器；记录 GPU/CPU 分配和内存 |
| 交付 | 保留基座 revision、adapter、合并权重、tokenizer、GGUF、Modelfile、依赖版本和测试结果 |

若 HF adapter 与 HF merged 已经差很多，先排查合并；HF merged 与 Ollama FP16 差很多，先排查转换和模板；FP16 正常而 Q4 明显下降，再研究量化精度。按这个顺序能把故障范围缩小。

## 7. 手机作为后续扩展

等 PC 路线跑完，再确认手机型号、系统和内存。没有这些信息时，不应承诺具体手机一定跑得动或给出 token/s。

| 设备 | 起步方向 | 需要额外学习 |
| --- | --- | --- |
| Android | llama.cpp 官方 Android 示例；先跑现成 0.5B Q4，再替换为自己的 GGUF | Android Studio、NDK、ARM64、模型文件导入、本地推理调用 |
| iPhone/iPad | llama.cpp 项目中的 Apple/Swift 示例与构建说明 | macOS、Xcode、签名、真机内存与 Metal；仅有 Windows PC 无法完成标准 iOS 原生构建流程 |

Android 路线参考 [llama.cpp 官方 Android 文档](https://github.com/ggml-org/llama.cpp/blob/master/docs/android.md)。Apple 示例入口可从 [llama.cpp 官方仓库](https://github.com/ggml-org/llama.cpp)确认，移动端接口随版本变化，实作时固定 commit。

注意：前面的转换步骤显式生成了 FP16 GGUF，而 `ollama create --quantize` 把 Q4 结果放进 Ollama 自己的模型存储。若手机应用需要独立 `.gguf` 文件，应另外导出 Q4 文件。可从 [llama.cpp 官方 Releases](https://github.com/ggml-org/llama.cpp/releases)下载适合 Windows x64 的 CPU 工具包，完整解压至项目根目录的 `tools\llama`（保留 DLL），确认其中有 `llama-quantize.exe` 后执行：

```powershell
Set-Location D:\workspace\pretrain-model
& .\tools\llama\llama-quantize.exe .\models\qwen-merged-f16.gguf .\models\qwen-merged-q4_k_m.gguf Q4_K_M
```

再把 `qwen-merged-q4_k_m.gguf` 导入手机端应用。这个 CPU 量化步骤无需编译 CUDA；记录工具包版本，并在手机上重新验收该文件。

手机第一轮按 0.5B、Q4、上下文 512、单会话、短回答开始；这是一组起步配置，不是内存保证。验收包含飞行模式下生成、首 token 延迟、生成速度、进程内存、连续使用时的温升和系统是否杀进程。

训练仍在 PC 做，手机先只负责推理。最终可以把同一份 GGUF 作为跨端实验的模型文件，但不同应用支持的架构、tokenizer 和模板仍需核对。

完成标准是：0.5B Q4 能由本机 Ollama 加载，通过本地 API 对固定测试集运行，并在模型已下载后断网生成；手机部署仍是可选扩展。
