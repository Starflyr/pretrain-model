# Windows 环境与从零预训练

[返回路线总览](./README.md)。所有命令在 **Windows PowerShell** 中执行；不要把 Linux 的 `source`、`export`、反斜杠续行直接贴进 PowerShell。

## 1. 安装最少的软件

安装 64 位 Python 3.12、Git 和一个编辑器（如 VS Code）。Python 可从 [Python Windows 下载页](https://www.python.org/downloads/windows/)取得，Git 从 [Git 官方安装页](https://git-scm.com/install/windows)取得。安装 Python 时启用 PATH 与启动器选项，重新打开 PowerShell。

```powershell
py -3.12 --version
git --version
nvidia-smi
New-Item -ItemType Directory -Force D:\llm-lab
Set-Location D:\llm-lab
```

`nvidia-smi` 中的 CUDA Version 是驱动支持的 CUDA 版本信息，不是“已经安装了同版本 Toolkit”的证据。驱动、PyTorch 使用的 CUDA runtime、用于编译 CUDA 程序的 Toolkit 是不同组件。通常使用官方预编译 PyTorch wheel 就能训练，本路线起步不需要 `nvcc`。

先用 **Windows 原生环境**，暂时不引入 WSL、Docker、DeepSpeed 或 FlashAttention 源码编译。它们不是这三个小实验的前置条件。

## 3. 安装 GPU 版 PyTorch 并验收

为了减少教学代码 API 变动，以下采用 **PyTorch 2.8.0 + CUDA 12.6 wheel** 作为版本基线，不表示它是最新版本，也不表示这套组合已经在你的电脑实测。先确认驱动可支持 CUDA 12.6；若 `nvidia-smi` 显示更低版本，先更新到适配该笔记本的 NVIDIA 驱动，或从官方页面选择兼容构建，不要盲装此命令。

```powershell
python -m pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cu126
python -m pip install numpy requests tiktoken
python -m pip check
```

安装命令依据 [PyTorch 官方历史版本页](https://pytorch.org/get-started/previous-versions/)；需要改用新版本时参考[官方安装选择器](https://pytorch.org/get-started/locally/)，并重新完成下面的验收。文本实验无需安装 torchvision 或 torchaudio。

把以下内容保存为 `D:\llm-lab\check_gpu.py`：

```python
import torch

print("PyTorch:", torch.__version__)
print("CUDA runtime:", torch.version.cuda)
print("CUDA available:", torch.cuda.is_available())
assert torch.cuda.is_available(), "先排查 GPU 版 PyTorch 与驱动，不要继续训练"
print("GPU:", torch.cuda.get_device_name(0))
print("VRAM GiB:", torch.cuda.get_device_properties(0).total_memory / 1024**3)
x = torch.randn(512, 512, device="cuda", requires_grad=True)
loss = (x @ x).square().mean()
loss.backward()
torch.cuda.synchronize()
print("GPU forward/backward OK; loss:", loss.item())
```

```powershell
python D:\llm-lab\check_gpu.py
python -m pip freeze > D:\llm-lab\requirements-pretrain-resolved.txt
```

必须满足：CUDA available 为 True、识别到 RTX 3050、GPU 前向与反向运算成功。仅有 `nvidia-smi` 成功不算 PyTorch 环境验收通过。

在进入语言模型之前，建议先把下面代码保存成 `D:\llm-lab\first_train.py`，运行 `python D:\llm-lab\first_train.py`。它学习 `y = 2x + 1`，只含两个可训练参数，方便你把已有编程经验对应到训练概念：

```python
import torch

torch.manual_seed(42)
x = torch.linspace(-1, 1, 100, device="cuda").reshape(-1, 1)
y = 2 * x + 1
model = torch.nn.Linear(1, 1).to("cuda")
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
for step in range(200):
    prediction = model(x)                  # 前向：用当前参数做预测
    loss = (prediction - y).square().mean() # 损失：预测差了多少
    optimizer.zero_grad()                  # 清空上一轮梯度
    loss.backward()                       # 反向：计算各参数的梯度
    optimizer.step()                      # 更新：沿降低损失的方向调整参数
    if step % 40 == 0:
        print(step, loss.item())
print("weight:", model.weight.item(), "bias:", model.bias.item())
```

验收：loss 下降，weight 接近 2、bias 接近 1。语言模型也有这几个核心步骤，只是输入变成 token、模型变成 Transformer、损失变成交叉熵、参数更多。

## 4. 用 nanoGPT 跑第一个从零预训练

[nanoGPT](https://github.com/karpathy/nanoGPT)代码较短，适合追踪训练循环。本实验沿用其公开的小型 Shakespeare 字符语料和字符编码方式，权重随机初始化，不下载 GPT-2 权重。它展示小型 Decoder-only Transformer 的训练流程，不覆盖工业级数据和分布式基础设施。

```powershell
Set-Location D:\llm-lab
git clone https://github.com/karpathy/nanoGPT.git
Set-Location D:\llm-lab\nanoGPT
git rev-parse HEAD > ..\nanogpt-revision.txt
python data/shakespeare_char/prepare.py
```

成功后检查 `data/shakespeare_char/` 中的 `train.bin`、`val.bin`、`meta.pkl`。原示例约按 90%/10% 切分文本，适合最小训练/验证演示；它从整份文本收集字符表，第二轮严谨实验应改为仅从训练集拟合词表并处理未知字符，另留独立测试文本，不能把反复调参的验证集当最终测试集。

先卸载 Ollama 占用的模型，在另一个 PowerShell 窗口执行 `ollama ps`，对已加载模型执行 `ollama stop 模型名`。如果还没有安装 Ollama，就跳过。训练和本地聊天不要同时争用 4GB 显存。

为了记录“还没训练时”的输出，在 nanoGPT 根目录保存 `sample_untrained.py`：

```python
import pickle
import torch
from model import GPT, GPTConfig

with open("data/shakespeare_char/meta.pkl", "rb") as f:
    meta = pickle.load(f)  # 只读取上一步自己生成的字符表
torch.manual_seed(1337)
model = GPT(GPTConfig(vocab_size=meta["vocab_size"], block_size=128,
                      n_layer=4, n_head=4, n_embd=128, bias=False)).to("cuda").eval()
x = torch.tensor([[meta["stoi"][c] for c in "ROMEO:"]], device="cuda")
with torch.inference_mode():
    y = model.generate(x, max_new_tokens=200, temperature=0.8, top_k=65)
print("".join(meta["itos"][i] for i in y[0].tolist()))
```

```powershell
python sample_untrained.py | Tee-Object -FilePath untrained-output.txt
```

这段只生成随机初始化基线，不更新参数。生成完进程会退出并释放显存；之后正式训练仍从头初始化。后续用相同提示比较文字形态即可，不把两次采样差异当成严格的性能指标。

第一轮只跑 100 步，验证数据、反向传播、验证与保存是否通：

```powershell
python train.py config/train_shakespeare_char.py --device=cuda --compile=False --dtype=float16 --init_from=scratch --n_layer=4 --n_head=4 --n_embd=128 --block_size=128 --batch_size=4 --gradient_accumulation_steps=4 --max_iters=100 --eval_interval=50 --eval_iters=10 --warmup_iters=10 --lr_decay_iters=100 --log_interval=10 --out_dir=out-smoke
```

正式第一轮：

```powershell
python train.py config/train_shakespeare_char.py --device=cuda --compile=False --dtype=float16 --init_from=scratch --n_layer=4 --n_head=4 --n_embd=128 --block_size=128 --batch_size=4 --gradient_accumulation_steps=4 --max_iters=2000 --eval_interval=200 --eval_iters=20 --warmup_iters=100 --lr_decay_iters=2000 --log_interval=10 --out_dir=out-tiny | Tee-Object -FilePath train-tiny.log
```

这是完整的模型训练，不要求参数量达到通常所说的“大模型”规模。`--init_from=scratch` 是检查重点；改成 `gpt2` 等预训练权重入口就不是从随机初始化训练了。

本配置每次优化器更新处理约 `4 × 128 × 4 = 2048` 个字符 token，2000 步约处理 409.6 万个 token，包含重复抽样，不代表拥有 409.6 万条不同数据。梯度累积提高有效 batch，不把每次前向 batch 直接扩大到 16。

参数解释：`n_layer` 是层数；`n_head` 是注意力头数；`n_embd` 是隐藏维度；`block_size` 是序列长度；`batch_size` 是一次前向的样本数。`compile=False` 避免第一轮混入编译环境问题。

## 5. 生成文本与恢复训练

```powershell
python sample.py --out_dir=out-tiny --device=cuda --compile=False --dtype=float16 --start="ROMEO:" --num_samples=2 --max_new_tokens=200 --temperature=0.8 --seed=1337
```

保留生成结果。预期可能从杂乱字符逐渐变得像英文词、人物对话和戏剧格式，不要求回答问题。字符词表只能编码它收录的字符，不要直接输入中文提示。

若在加载自己训练的 checkpoint 时出现 `Weights only load failed`，检查 `train.py` 和 `sample.py` 中的 `torch.load(ckpt_path, map_location=device)`。部分旧版脚本与 PyTorch 2.6+ 的默认加载行为不同，可针对**自己刚训练生成的可信文件**改为：

```python
checkpoint = torch.load(ckpt_path, map_location=device, weights_only=False)
```

不要对来历不明的 `.pt` 文件这么做。相关行为见 [PyTorch 序列化说明](https://pytorch.org/docs/stable/notes/serialization.html)。这是加载旧 checkpoint 的兼容步骤，和训练效果没有关系。

恢复前先保留一份实验结果：

```powershell
Copy-Item -Recurse out-tiny out-tiny-before-resume
```

重用完整的正式训练命令，把 `--init_from=scratch` 改成 `--init_from=resume`，`--max_iters=2000` 改为 `--max_iters=2500`，保持 `--out_dir=out-tiny`。这是练习从保存点继续优化；若修改 `lr_decay_iters`，也改变了学习率计划，需写进实验记录。恢复步数以 checkpoint 实际保存的位置为准。

nanoGPT 的 checkpoint 包含权重、优化器等状态，但原脚本不完整保存所有随机数和 AMP scaler 状态，不应把这项练习理解为逐位一致的断点恢复。

## 6. 怎样证明自己学会了

验收时应该能展示：

1. 数据文件与字符词表；能解释 token 如何变为数字。
2. 日志中的随机初始化提示、参数量、train loss 和 val loss。
3. `out-tiny/ckpt.pt`；关闭训练进程后仍可加载生成。
4. 同一提示在两个训练阶段的输出比较。
5. 一次恢复训练记录和一次只改一个参数的对照实验。

读 `train.py` 的 `get_batch`：输入是连续字符，标签向右错开一位。在训练循环找到 forward、loss、backward、optimizer step；到 `model.py` 找 embedding、因果注意力和生成循环。**能把这几处代码连起来，比把训练步数增加十倍更值得优先做。**

第二轮只把 `n_embd=128` 改为 `256`，用新 `out_dir` 从零开始；或者保持模型不变，仅把 `block_size=128` 改为 `256`，不要同时修改多个变量。显存不够就按 `batch 4 → 2 → 1`、`长度 128 → 64` 调整。

训练 loss 下降、验证 loss 上升，往往是在过拟合。loss 为 NaN、长期不动、保存/加载失败，都需要排查，不能只看进度条跑完。

## 7. 可选：把“从零”做得更深入

完成英文字符实验后，选择一种已获得使用许可的中文语料，小规模清洗、去重并按原始文档划分训练/验证/测试集。先只在训练集拟合 tokenizer，再编码各数据集。使用 2K～4K 的小 BPE 词表和小 Transformer，观察 tokenizer 改变后词表、序列长度和参数量的变化。

这一步结合 Happy-LLM 第 5 章完成，不要直接照搬其大词表与模型规模。目标是补齐“训练 tokenizer”的经验；不是立即训练通用中文聊天模型。

## 故障速查

| 表现 | 优先检查 |
| --- | --- |
| `py` / `python` 不存在 | Python 安装与 PATH；安装后重新开 PowerShell |
| `torch.version.cuda` 为 None | 装成了 CPU 版；确认在正确虚拟环境中安装 CUDA wheel |
| CUDA False 或 DLL 错误 | Python 位数、解释器路径、官方 wheel、驱动；DLL 缺失时再检查微软 VC++ 运行库 |
| GPU OOM | 先停掉其他模型和占显存程序；减 batch，再减长度，最后缩小模型 |
| `nvcc` 不存在 | 本路线起步并不需要 nvcc；先看 GPU 张量验收是否通过 |
| 下载超时 | 区分 PyPI、GitHub、模型站点的网络问题；可浏览器下载官方文件后放到指定目录 |
| 恢复后结果有些差异 | 随机数、AMP scaler、抽样、学习率计划等并非全部恢复 |
